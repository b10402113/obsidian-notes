# 高級篇實操總結

## 📝 程概述
本節課是「高級篇」的最後一節正課，以視頻形式演示 PV/PVC、NFS 網絡存儲卷、StatefulSet、滾動更新、水平自動伸縮、Prometheus 監控和 Dashboard 部署等重要操作，幫助學員將理論知識轉化為實際操作能力。

## 核心觀念與實作解析

### PV 和 PVC 實操

**創建流程**：

1. 在節點上創建目錄：`mkdir /tmp/host-10m-pv`
2. 定義 PV（storageClassName、accessModes、capacity、hostPath）
3. 定義 PVC（申請容量，Kubernetes 會查找匹配的 PV 並綁定）
4. 在 Pod 中用 `persistentVolumeClaim` 指定 PVC 名稱

**驗證持久化**：進入容器寫入文件後，登錄節點查看 PV 目錄，確認文件存在。

### NFS 網絡存儲卷

**前置條件**：安裝 NFS 服務器、客戶端和 NFS Provisioner，配置 StorageClass 名稱為 `nfs-client`。

**關鍵特性**：NFS 支持多 Pod 同時挂載，訪問模式使用 `ReadWriteMany`。NFS Provisioner 自動創建 PV，容量精確匹配 PVC 申請。

### StatefulSet 實戰

**YAML 關鍵字段**：
- `serviceName`：指定 Headless Service
- `volumeClaimTemplates`：PVC 模板，每個 Pod 自動創建獨立 PVC

**三大特性驗證**：
- Pod 名字順序編號（redis-pv-sts-0、redis-pv-sts-1）
- 穩定域名可正常訪問（`ping redis-pv-sts-0.redis-svc`）
- 刪除 Pod 後數據自動恢復

### 滾動更新

**版本更新流程**：
- `kubectl apply -f ngx-v2.yml`：觸發滾動更新
- `kubectl rollout status deploy ngx-dep`：查看更新狀態
- `kubectl rollout history deploy ngx-dep`：查看更新歷史
- `kubectl rollout undo deploy ngx-dep`：回退版本

YAML 中用 `annotations.kubernetes.io/change-cause` 標註版本信息。

### 水平自動伸縮 (HPA)

**前置條件**：Metrics Server 運行正常，Deployment 必須定義 `resources` 赬源配額。

**HPA 定義**：指定 `minReplicas`、`maxReplicas` 和 CPU 使用率目標。HPA 透過 Metrics Server 監測 CPU 使用率，超過設定值自動擴容。

**壓力測試**：使用 `ab` 工具發送大量請求，觀察 HPA 自動擴容效果。

### Prometheus 監控

**部署步驟**：下載源碼包，修改 Service 為 NodePort（Prometheus: 30090，Grafana: 30030），修改鏡像地址避免 gcr.io 拉取困難。

**使用方式**：
- Prometheus：使用 PromQL 查詢指標生成圖表
- Grafana：預置多種 Kubernetes 仪表盘

### Dashboard 部署

**完整流程**：
1. 應用官方 YAML
2. 生成 TLS 證書並創建 Secret
3. 配置 Ingress Class、Ingress（annotations 指定 HTTPS 後端）、Ingress Controller
4. 創建管理員賬號（RBAC機制）
5. 獲取 Token 登錄，訪問 `https://k8s.test:30443`

## 💡 重點摘要

- **PV/PVC 验证**：Pod 数据寫入容器挂載目錄，節點上對應目錄能看到相同數據
- **NFS 网络存储**：NFS Provisioner 自動創建 PV，服务器上文件能出现在容器里
- **StatefulSet 特性**：Pod 順序編號、獨立域名、自動創建 PVC，Pod 删除後數據自動恢復
- **滾動更新**：apply 更新 → rollout status 查看狀態 → rollout history 查看歷史 → undo 版本回退
- **HPA 伸縮**：Metrics Server 采集指標，HPA 监测 CPU 使用率，超過阈值自動擴容
