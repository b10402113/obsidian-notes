# 容器與外界互通：数据與網路連接

## 課程概述
本課程說明如何打破容器的隔離環境，讓容器與宿主機進行数据交換與網路通信，包括文件拷貝、目录共享、網路模式與端口映射等實用技巧。

## 核心觀念與實作解析

### 容器為何需要與外界互通？
- 容器是「沙盒」環境，完全隔離會導致服務無法对外提供
- 需要「有限的隔離」：開门窗讓應用與外界交換数据、互通有无
- 對 Nginx、Redis、MySQL 等服務尤為重要

### 数据交換方法

#### 方法一：docker cp 拷貝文件
类似 Linux 的 `cp`、`scp`，在宿主機與容器間拷貝文件。

```bash
docker run -d --rm redis                    # 啟動 Redis容器
docker cp a.txt 062:/tmp                    # 拷貝文件進容器（062為容器ID）
docker cp 062:/tmp/a.txt ./b.txt            #從容器拷貝文件出來
docker exec -it 062 sh                      #進入容器验证
```

#### 方法二：-v 参数共享目录
類似虛擬機的「共享目录」，兩边實時同步，效率更高。

```bash
docker run -d --rm -v /tmp:/tmp redis       #挂載宿主機 /tmp 到容器 /tmp
docker exec -it b5a sh                      #進入容器查看
```

**實用場景**：開發時在本機编写代码，容器内運行不同版本的环境（如 Python 3）。

```bash
docker pull python:alpine
docker run -it --rm -v `pwd`:/tmp python:alpine sh
```

### 網路通信模式

Docker 提供三種網路模式：

| 模式 | 特點 |适用場景 |
|------|------|--------|
| **null** |無網路 | 自定義網路插件 |
| **host** | 直接使用宿主機網路，共享IP與网卡 | 高效率但易端口冲突 |
| **bridge** | 虛擬網桥，私有網段互聯 | 默默使用，隔离性較好 |

#### host 模式
```bash
docker run -d --rm --net=host nginx:alpine     # 共享宿主機網路
docker exec xxx ip addr                        # 容器内网卡與宿主機完全相同
```

#### bridge 模式（默默）
```bash
docker run -d --rm nginx:alpine                #默默默使用 bridge
docker run -d --rm redis
docker inspect xxx |grep IPAddress             # 查看容器IP（如 172.17.0.2）
```

容器與宿主機都在 `172.17.0.0/16` 网段，彼此可用 IP 通信。

### 端口映射
解決多容器端口冲突問題，將宿主機端口映射到容器内部端口。

```bash
docker run -d -p 80:80 --rm nginx:alpine       # 宿主機80映射到容器80
docker run -d -p 8080:80 --rm nginx:alpine     # 宿主機8080映射到容器80
curl 127.1:80 -I                               # 验证服務可访问
```

`-p` 参数格式：`宿主機端口:容器端口`

### docker cp 与 COPY 指令的區別
| 命令 | 埴行時機 | 特點 |
|------|----------|------|
| Dockerfile `COPY` | 构建鏡像時 | 文件永久存在於鏡像中 |
| `docker cp` |容器運行時 | 臨時拷貝，不影響鏡像 |

### host 与 bridge 模式比較
| 特性 | host 模式 | bridge 模式 |
|------|-----------|-------------|
| 效率 | 高（無中間層） |較低（經虛擬網桥） |
| 隔离性 | 差（共享網路） | 好（私有網段） |
| 端口冲突 | 易發生 | 可用映射避免 |
| 适用場景 | 集群邊界通信 | 集群内部通信 |

## 重點摘要
- `docker cp` 可在宿主機與容器間拷貝文件，適合簡單数据交換
- `-v` 参数可共享目录，實時同步，適合開發调试
- host 模式效率高但易端口冲突，bridge 模式隔离性好
- `-p` 参数映射端口，避免多容器端口冲突

## 關鍵字
docker cp, -v, host mode, bridge mode, port mapping
