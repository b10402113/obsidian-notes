# 容器的本質：被隔離的進程

##課程概述
本課程深入探討「容器」的核心概念，說明容器如何透過 Linux内核的 namespace、cgroup、chroot 技術實現進程隔離，並與虛擬機技術進行比較，理解容器輕量高效的原因。

## 核心觀念與實作解析

### 容器是什麼？
- **容器 = 被隔離的進程**，運行在特殊的「沙盒」環境中
- 容器與外部系統互相隔離，進程只能看到環境內的有限資訊
- 形象比喻：如同現實世界的「集装箱」，封裝應用程式，實現標準化運輸與管理

###實際操作觀察容器隔離
```bash
docker pull alpine                    #拉取 Alpine鏡像
docker run -it alpine sh              #進入容器内部
cat /etc/os-release                   # 查看系統資訊（已變成 Alpine Linux）
ps                                    # 查看進程（只有 Shell，完全乾淨）
exit                                  # 退出容器
```

容器内部是一個全新的 Alpine 系統，與外部的 Ubuntu 完全隔離，形成「世外桃源」。

### 為什麼需要隔離？
隔離的目的：**系統安全與資源管理**

1. **安全考量**：防止進程無限制訪問系統資源，避免惡意程序破壞系統
2. **資源配額**：限制進程可使用的 CPU、記憶體等資源，避免過度消耗

容器就像「隔离酒店」，進程可在内自由活動，但絕不允许「越界」。

### 容器與虛擬機的比較
| 特性 | 虛擬機 | 容器 |
|------|--------|------|
| 隔離層次 | 硬體層（Hypervisor） | 操作系統層 |
| 資源消耗 | 重（需完整 OS） |輕量（共享内核） |
| 啟動速度 | 數分鐘 | 秒級 |
| 體積大小 | GB 级别 | MB 级别 |
| 隔離程度 | 完全隔離 | 共享内核，隔離程度較低 |

容器直接利用底層硬體與操作系统，比虛擬機少一層，**更高效利用硬體資源**。

### 隔離技術的實現原理
Linux内核提供三種技術組合實現容器隔離：

1. **namespace**（2002年，Linux 2.4.19）
   - 創建獨立的文件系統、主機名、進程號、網路等資源空間
   - 相當於為進程「蓋了一間小板房」

2. **cgroup**（2008年，Linux 2.6.24）
   - Linux Control Group，實現 CPU、記憶體等資源的配額限制
   - 相當於為進程的小板房「加了一個天花板」

3. **chroot**（1979年，UNIX V7）
   - 更改進程的根目錄，限制文件系統訪問
   - 相當於為進程的小板房「鋪上地砖」

三種技術組合，形成完善的容器隔離環境。

##重點摘要
- 容器是操作系統中特殊的「沙盒」環境，進程與外界實現隔離
- 隔離目的為系統安全與資源管理，限制進程可訪問的資源範圍
- 容器比虛擬機輕巧高效，消耗資源少，適合雲計算時代
- 容器實現技術為 Linux 的namespace、cgroup、chroot
