# 迎難而上，做雲原生時代的弄潮兒

## 📝 課程概述

本文是《Kubernetes 入門實戰課》的開篇詞，講師 Chrono 分享自身從忽視到重視容器技術的經歷，闡述學習 Kubernetes 的重要性，並介紹課程的設計理念與學習路徑。

## 核心觀念與實作解析

### 為什麼要學 Kubernetes

Kubernetes 已成為雲原生時代的**事實作業系統**：

- 自 2013 年 Docker 誕生後，容器成為 IT 界最熱門話題
- Kubernetes 擊敗 Docker Swarm 和 Apache Mesos，成為容器編排領域的王者
- 地位如同 Linux，是現代應用（微服務、服務網格）的基石

無論是研發、測試、運維，無論使用何種語言或技術，Kubernetes 都是繞不過去的產品。

### Kubernetes 技術棧特點：新、廣、雜、深

| 特點 | 說明 |
|------|------|
| **新** | 採用前沿、陌生的技術，版本更新快 |
| **廣** | 涉及領域多，難以找到合適切入點 |
| **雜** | 各種實現雜亂，令人眼花撩亂 |
| **深** | 每個具體問題都需要深厚的技術背景 |

這四個特點導致 Kubernetes 的門檻相當高，學習曲線陡峭。

### 初學者常見困惑

課程列舉了初學者經常遇到的問題：

- Docker、Containerd、K8s、K3s、MicroK8s、Minikube...如何選擇？
- 容器概念抽象，如何快速準確理解？
- 映像檔命名稀奇古怪，`bionic`、`buster` 是什麼意思？
- 如何搭建 Kubernetes 環境？
- YAML 檔案又長又亂，有無規律可循？
- Pod、Deployment、StatefulSet...這麼多物件有什麼內在聯繫？

### 課程設計理念

#### 1. 沒有太多前提，不會 Go 也可以學

- 不要求學習 Go 語言
- 不講 Kubernetes 源碼
- 講師與學員站在同一起跑線

#### 2. 定位在「入門」

- 不講高深的大道理和複雜的工作流程
- 語言樸素平實，少用專業術語
- 盡快建立全局觀和大局觀

#### 3. 以實戰為導向

- 選用 Kubernetes 1.23.3（最後一個支援 Docker 的大版本）
- 從 Docker 開始，陸續使用 minikube、kubeadm 搭建環境
- 給出大量 docker、kubectl 操作指令

#### 4. 每節課聚焦一個知識點

- 不「貪大求全」，而是「短小精悍」
- 做減法而非加法
- 搭配圖片幫助理解複雜概念

### 課程模組結構

課程採用**線性結構**，將 Kubernetes 知識點從網狀簡化為線性：

| 模組 | 內容 |
|------|------|
| **課前準備** | 搭建實驗環境，虛擬機軟體與 Linux 系統 |
| **入門篇** | Docker 基礎技術：容器原理、常用指令、映像檔構建 |
| **初級篇** | 單機環境 minikube：架構、YAML、Pod、Job/CronJob、ConfigMap/Secret |
| **中級篇** | 多節點叢集 kubeadm：Deployment、DaemonSet、Service、Ingress |
| **高級篇** | 深層知識：持久化存儲、有狀態物件、滾動更新、自動伸縮 |

### 補充學習形式

- **知識小貼士**：每節課後的補充內容
- **互動答疑**：解答學員疑問
- **加餐**：docker-compose、CNCF、API Gateway 等周邊知識
- **實戰演練課**：從單機應用到高可用系統的 WordPress 網站搭建
- **視頻課**：實機操作演示

## 💡 重點摘要

- Kubernetes 已成為雲原生時代的事實作業系統，學習它已是勢在必行
- 技術棧特點為「新、廣、雜、深」，導致學習門檻高、曲線陡峭
- 課程定位「入門」，不要求 Go 語言基礎，不講源碼
- 採用線性結構，每節課聚焦單一知識點，搭配實戰演練與視頻
- 學習 Kubernetes 最好的方式是盡快建立全局觀，再挑選感興趣的方向深入研究
