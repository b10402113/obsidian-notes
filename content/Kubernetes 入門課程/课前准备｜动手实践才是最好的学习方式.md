# 課前準備｜動手實踐才是最好的學習方式

## 📝 課程概述

本節課指導學員在正式學習 Kubernetes 之前，如何從零開始搭建一個完整的實驗環境。強調「工欲善其事，必先利其器」的重要性，透過本地虛擬機環境的搭建，讓後續學習能夠事半功倍。

## 核心觀念與實作解析

### 為什麼需要實驗環境？

Kubernetes 是一個貼近生產環境的龐大系統，與網路協議、程式語言不同，如果「光說不練」，即使掌握再多知識，但無法與實際相結合，也只能是「紙上談兵」。一個完善的實驗環境能夠讓學員熟悉操作命令、驗證測試各種特性。

### 選擇實驗環境方案

講師建議在本地使用虛擬機搭建實驗環境，原因如下：

- **雲主機的限制**：需要付費、受網路和廠商限制、難以真正「從零搭建」
- **虛擬機的優勢**：完全自主可控、成本極低、可隨意建立刪除
- **額外好處**：雲服務商內部大量使用虛擬伺服器，Kubernetes 的容器技術與虛擬機有許多相似之處

### 硬體配置建議

- **CPU**：4 核（最低 2 核）
- **記憶體**：最少 8G（虛擬機和 Kubernetes 都很耗記憶體）
- **硬碟**：300G（虛擬機硬碟 40G 以上）
- 可支援開 2-3 台虛擬機組成最小集群

### 虛擬機軟體選擇

| 軟體 | 適用平台 | 說明 |
|------|----------|------|
| **VirtualBox** | Intel (x86_64) 晶片 | Oracle 推出，免費、無使用限制 |
| **VMWare Fusion** | Apple M1 (arm64) 晶片 | 技術預覽版免費，約 300 天使用期限 |

> **注意**：VirtualBox 不支援 Apple M1 晶片，M1 Mac 用戶需選擇 VMWare Fusion。

### 作業系統選擇

建議選擇 **Ubuntu 22.04 Jammy Jellyfish 桌面版**，原因：

- 易用性高，適合學習
- 同時支援 x86_64 和 arm64
- 有足夠新的特性，適合運行 Kubernetes
- 內建瀏覽器、終端機等工具方便除錯測試

### 虛擬機配置要點

#### 資源配置

- **CPU**：2 核（最低要求）
- **記憶體**：2G（最低），建議 4G
- **硬碟**：40G 以上
- 可停用聲卡、攝影機、軟碟機等非必要設備

#### 網路配置

**VirtualBox 設定**：
1. 在「工具 - 網路」建立「Host-only」網路（如 192.168.56.1/24）
2. 虛擬機啟用兩張網卡：
   - 網卡 1：Host-only（本地終端登入用）
   - 網卡 2：NAT（連外網用）

**VMWare Fusion 設定**：
1. 在「偏好設定 - 網路」新增自訂網路（如 vmnet3）
2. 允許 NAT 連接外網

### 安裝步驟

1. 載入 Ubuntu 22.04 光碟映像檔
2. 選擇「最小安裝」，**物理斷網**（避免下載升級包，M1 Mac 尤其重要）
3. 安裝完成後執行環境初始化：
   ```bash
   sudo apt update
   sudo apt install -y git vim curl jq
   sudo apt install -y openssh-server
   ip addr  # 查看 IP 地址
   ```
4. 設定靜態 IP（可選）
5. **拍攝快照備份**（環境出問題可隨時回滾）

### Linux 常用操作複習

| 命令 | 說明 |
|------|------|
| `ps` | 查看系統當前進程列表 |
| `cat` / `more` / `less` | 查看檔案內容 |
| `vim` | Linux 最流行的編輯器 |
| `curl` | 以命令行發送 HTTP 請求 |
| `sudo` | 臨時使用 root 權限 |

## 💡 重點摘要

- **實驗環境必不可少**：Kubernetes 實踐性大於理論性，必須動手操作才能真正掌握
- **本地虛擬機最佳**：不受雲端限制、完全自主可控、成本低廉
- **選擇合適的工具組合**：VirtualBox + Ubuntu（Intel）或 VMWare Fusion + Ubuntu（M1 Mac）
- **網路配置是關鍵**：需設定 Host-only 和 NAT 雙網卡
- **快照備份是安全網**：環境設定好後立即備份，出問題可快速回滾
