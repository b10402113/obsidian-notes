# 集群管理：名字空間的資源分隔策略

## 📝 課程概述

本課程探討 Kubernetes 集群管理中的核心概念——名字空間（Namespace）。課程詳細說明名字空間的作用與意義，並介紹 ResourceQuota 和 LimitRange 兩種資源配額對象，實現對集群資源的精細化管理，避免多團隊共用集群時的命名冲突和资源争抢問題。

## 核心觀念與實作解析

### 理解名字空間的概念

#### 名字空間的定義

Kubernetes 的名字空間**不是實體對象，只是一個邏輯概念**。它可以把集群切分成彼此獨立的区域，把对象放到这些区域里，实现类似容器技術里 namespace 的隔离效果：
- 应用只能在自己的名字空间里分配资源和运行
- 不会干扰到其他名字空间里的应用

#### 為什麼需要名字空間？

在大规模集群、海量节点的环境中，会有非常多的用户创建各式各样的应用，可能有百万数量级别的 Pod，这就使得**资源争抢和命名冲突的概率大大增加**。

**命名冲突的例子**：
- 后端组创建了 Pod "Web"
- 前端组和测试组只能绞尽脑汁再新起一个不冲突的名字

**资源争抢的例子**：
- 测试组部署了有 Bug 的应用
- 把节点上的资源都给「吃」完了
- 其他组的同事无法工作

名字空間把集群適當「局部化」，為每一類用户創建出只屬於它自己的「工作空间」。

比喻：
- Kubernetes：大牧场
- API 对象：鸡鸭牛羊
- 名字空间：圈养的围栏

### 名字空間的基本使用

#### Kubernetes 預設的名字空間

Kubernetes 初始化集群时预设 4 个名字空间：
- **default**：用户对象默认的名字空间
- **kube-system**：系统组件所在的名字空间
- **kube-public**：公共资源
- **kube-node-lease**：节点租约信息

#### 创建和使用名字空間

创建名字空間：

```bash
kubectl create ns test-ns
kubectl get ns
```

將对象放入特定名字空間，在 metadata 里添加 namespace 字段：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: ngx
  namespace: test-ns

spec:
  containers:
  - image: nginx:alpine
    name: ngx
```

**查看其他名字空間的对象**：

```bash
kubectl get pod -n test-ns
```

**注意**：默认查看的是 default 名字空间，操作其他名字空间必须用 `-n` 参数明确指定。

#### 删除名字空間的風險

删除名字空間时，它里面的所有对象也会消失：

```bash
kubectl delete ns test-ns
```

名字空間里的对象都从属于名字空间，删除名字空间一定要小心。

### ResourceQuota：名字空間的資源配額

#### ResourceQuota 对象的作用

有了名字空間，可以像管理容器一样，给名字空間设定配額：
- 把整个集群的计算资源分割成不同的大小
- 按需分配给团队或项目使用

除了限制最基本的 CPU 和内存，还必须限制各种对象的数量，否则对象之间也会互相挤占资源。

#### ResourceQuota 的 YAML 定义

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: dev-ns

---

apiVersion: v1
kind: ResourceQuota
metadata:
  name: dev-qt
  namespace: dev-ns

spec:
  hard:
    requests.cpu: 10
    requests.memory: 10Gi
    limits.cpu: 10
    limits.memory: 20Gi

    requests.storage: 100Gi
    persistentvolumeclaims: 100

    pods: 100
    configmaps: 100
    secrets: 100
    services: 10

    count/jobs.batch: 1
    count/cronjobs.batch: 1
    count/deployments.apps: 1
```

#### 资源配額的分类

**1. CPU 和内存配額**
- 使用 `requests.*`、`limits.*`
- 和容器资源限制一样

**2. 存储容量配額**
- `requests.storage`：限制 PVC 的存储总量
- `persistentvolumeclaims`：限制 PVC 的个数

**3. 核心对象配額**
- 使用对象的名字（英语复数形式）
- 例如：`pods`、`configmaps`、`secrets`、`services`

**4. 其他 API 对象配額**
- 使用 `count/name.group` 的形式
- 例如：`count/jobs.batch`、`count/deployments.apps`

#### ResourceQuota 的含義示例

- 所有 Pod 的需求总量最多 10 个 CPU 和 10GB 内存
- 上限总量 10 个 CPU 和 20GB 内存
- 只能创建 100 个 PVC，使用 100GB 持久化存储
- 只能创建 100 个 Pod、100 个 ConfigMap、100 个 Secret、10 个 Service
- 只能创建 1 个 Job、1 个 CronJob、1 个 Deployment

#### 分類限制資源（更靈活）

可以将配額拆成几个小的 YAML，分类限制：

```yaml
# CPU 和内存配額
apiVersion: v1
kind: ResourceQuota
metadata:
  name: cpu-mem-qt
  namespace: dev-ns

spec:
  hard:
    requests.cpu: 10
    requests.memory: 10Gi
    limits.cpu: 10
    limits.memory: 20Gi
```

```yaml
# 核心对象配額
apiVersion: v1
kind: ResourceQuota
metadata:
  name: core-obj-qt
  namespace: dev-ns

spec:
  hard:
    pods: 100
    configmaps: 100
    secrets: 100
    services: 10
```

#### ResourceQuota 的使用验证

创建配額后尝试创建两个 Job：

```bash
kubectl create job echo1 -n dev-ns --image=busybox -- echo hello
kubectl create job echo2 -n dev-ns --image=busybox -- echo hello
```

ResourceQuota 限制了最多只能有 1 个 Job，创建第二个 Job 会失败，提示超出资源配額。

删除刚才的 Job 后，可以运行新的离线业务。

### LimitRange：默認資源配額

#### ResourceQuota 的約束問題

有了 ResourceQuota 后，会要求所有 Pod 都必须用 `resources` 字段声明资源需求，否则无法创建：

```bash
kubectl run ngx --image=nginx:alpine -n dev-ns
# Forbidden 错误：不满足配額要求
```

原因：如果 Pod 没有 resources 字段，可以无限制使用 CPU 和内存，与名字空間的资源配額冲突。

这对集群管理是好事，但对普通用户带来麻烦，需要反复设置配額。

#### LimitRange 的作用

**LimitRange**（简称 limits）能为 API 对象添加默认的资源配額限制，让 Kubernetes 自动为 Pod 加上资源限制。

#### LimitRange 的 YAML 定义

```yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: dev-limits
  namespace: dev-ns

spec:
  limits:
  - type: Container
    defaultRequest:
      cpu: 200m
      memory: 50Mi
    default:
      cpu: 500m
      memory: 100Mi
  - type: Pod
    max:
      cpu: 800m
      memory: 200Mi
```

#### LimitRange 的关键字段

- **spec.limits**：核心属性，描述默认的资源限制
- **type**：要限制的对象类型
  - Container、Pod、PersistentVolumeClaim
- **default**：默认的资源上限，对应 `resources.limits`（只适用于 Container）
- **defaultRequest**：默认申请的资源，对应 `resources.requests`（只适用于 Container）
- **max、min**：对象能使用的资源的最大最小值

#### LimitRange 的含义

- 每个容器默认申请 0.2 CPU（200m）和 50MB 内存
- 容器的资源上限是 0.5 CPU（500m）和 100MB 内存
- 每个 Pod 的最大使用量是 0.8 CPU（800m）和 200MB 内存

#### LimitRange 的效果

创建 LimitRange 后，不用编写 resources 字段就能直接创建 Pod：

```bash
kubectl run ngx --image=nginx:alpine -n dev-ns
# 成功创建，LimitRange 自动加上资源配額
```

LimitRange 为 Pod 自动加上了资源配額作为「保底」。

## 💡 重點摘要

- **名字空间是逻辑概念**：不是实体对象，用于划分集群为独立区域，避免命名冲突和资源争抢
- **ResourceQuota 全局资源配额**：限制名字空间的 CPU、内存、存储容量和 API 对象数量
- **LimitRange 默认资源配额**：为容器或 Pod 自动添加默认的资源限制，简化对象创建工作
- **配额分类**：CPU/内存（requests/limits）、存储（storage/PVC）、核心对象（pods/configmaps/secrets/services）、其他对象（count/name.group）
- **生产环境的重要性**：多用户共用集群时，必须用名字空间做好集群的资源规划，公平合理利用资源
