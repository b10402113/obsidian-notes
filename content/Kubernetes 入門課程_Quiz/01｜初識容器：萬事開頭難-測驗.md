**Q2.** 關於 Docker Desktop 和 Docker Engine 的比較，以下哪項敘述正確？

A) Docker Desktop 完全免費，適合生產環境使用
B) Docker Engine 只能在 Linux 上運行，是生產環境的主流選擇
C) Docker Desktop 不支援 Mac 和 Windows 系統
D) Docker Engine 具有圖形化介面，操作更友善

   <details>
   <summary>答案</summary>
   <b>B) Docker Engine 只能在 Linux 上運行，是生產環境的主流選擇</b>

Docker Engine 是完全免費的產品，只能在 Linux 上運行，是各公司在生產環境中實際使用的 Docker 產品。Docker Desktop 雖然支援 Mac 和 Windows，但它是商業產品，對個人學習免費但不能商用，且可能包含非通用的功能，不利於後續學習 Kubernetes。

   </details>

**Q3.** 在 Ubuntu 系統中安裝 Docker Engine 後，需要執行哪個命令將當前用戶加入 Docker 用戶組？

A) `sudo useradd docker ${USER}`
B) `sudo usermod -aG docker ${USER}`
C) `sudo groupadd docker ${USER}`
D) `sudo adduser docker ${USER}`

   <details>
   <summary>答案</summary>
   <b>B) sudo usermod -aG docker ${USER}</b>

`usermod -aG` 命令用於將用戶添加到指定的用戶組。這是因為操作 Docker 必須要有 root 權限，而直接使用 root 用戶不夠安全，加入 Docker 用戶組是官方推薦的做法。注意執行此命令後需要退出並重新登錄才能生效。

   </details>

---

**Q4.** 在 Docker 的客戶端/伺服器架構中，以下哪個組件負責實際的管理工作？

A) Docker Client
B) Docker Registry
C) Docker Daemon
D) Docker API

   <details>
   <summary>答案</summary>
   <b>C) Docker Daemon</b>

Docker Daemon 是容器和鏡像的「大管家」，負責從遠端拉取鏡像、在本地存儲鏡像、從鏡像生成容器、管理容器等所有功能。命令行工具 docker（Client）只是個「傳聲筒」，真正幹活的是後台運行的 Docker Daemon。

   </details>

---

**Q5.** 執行 `docker run busybox echo hello world` 命令後，容器會處於什麼狀態？

A) 持續運行中
B) 已停止
C) 暫停中
D) 正在重啟

   <details>
   <summary>答案</summary>
   <b>B) 已停止</b>

當容器執行完指定的命令（`echo hello world`）後，容器就會自動停止。使用 `docker ps -a` 可以看到這個已經運行完畢的容器處於停止狀態。

   </details>

**Q7.** 使用 `docker ps` 命令不加任何參數時，會列出所有容器（包括已停止的容器）。 _(對/錯)_

   <details>
   <summary>答案</summary>
   <b>錯</b> - `docker ps` 默認只列出正在運行的容器。要查看所有容器（包括已停止的），需要加上 `-a` 參數，即 `docker ps -a`。

**Q8.** Docker Engine 安裝完成後，可以立即使用，無需進行任何額外配置。 _(對/錯)_

   <details>
   <summary>答案</summary>
   <b>錯</b> - Docker Engine 不像 Docker Desktop 那樣可以安裝後直接使用。需要執行 `sudo service docker start` 啟動 Docker 後台服務，並執行 `sudo usermod -aG docker ${USER}` 將當前用戶加入 Docker 組，退出並重新登錄後才能正常使用。
   </details>

**Q11.** 在 Docker 架構中，鏡像存儲在遠端的 **\_\_\_\_** 中，客戶端使用 **\_\_\_\_** 命令從中拉取鏡像。

   <details>
   <summary>答案</summary>

Registry 是存儲 Docker 鏡像的遠端倉庫。客戶端不能直接訪問 Registry，需要通過 Docker Daemon 使用 `docker pull` 命令從 Registry 拉取鏡像到本地。

   </details>

## 第四部分：簡答題（30 分）

**Q13.** 課程中提到 Docker Desktop 和 Docker Engine 兩種產品，作者為什麼推薦學習時使用 Docker Engine 而不是 Docker Desktop？

   <details>
   <summary>答案</summary>

作者推薦使用 Docker Engine 的原因主要有兩個：

1.  **避免商業限制**：Docker Desktop 是商業產品，雖然對個人學習免費，但受條款限制不能商用。在日常工作中可能會「踩到雷區」，而 Docker Engine 完全免費且開源。

2.  **更利於學習**：Docker Desktop 集成了許多周邊工具，可能包含 Docker 公司自己非通用的功能。而 Docker Engine 是 Docker 的「真正形態」，「血脈」最純正，是生產環境中實際使用的產品，更有利於後續學習 Kubernetes。

**關鍵點：**

- 完全免費，無商業限制
- 生產環境實際使用的產品
- 功能更純正，利於深入學習
- 機房 99% 的服務器運行 Linux
</details>

**Q14.** 請說明 Docker 採用客戶端/伺服器（C/S）架構的設計優勢是什麼？

   <details>
   <summary>答案</summary>

Docker 採用 C/S 架構的主要優勢：

1.  **功能模組分離**：客戶端和伺服器各自獨立，可以分別發展和升級，降低耦合度。

2.  **支援分布式應用**：可以運行一個 Docker Daemon，多個客戶端同時向這個伺服器發送命令，適合團隊協作和遠程管理。

3.  **安全性提升**：客戶端不需要 root 權限，只需加入 docker 組即可操作，降低安全風險。

4.  **靈活部署**：客戶端和伺服器可以部署在不同機器上，支援遠程操作 Docker 環境。

5.  **易於升級維護**：升級或重啟 Docker Daemon 不需要影響客戶端操作，可以實現不中斷服務的維護。

**關鍵點：**

- 解耦設計，獨立發展
- 支援分布式和遠程管理
- 安全性更高
- 維護更靈活
</details>

**Q15.** 課程中演示的 Docker 基本操作流程是什麼？請按照執行順序列出相關命令並說明其作用。

   <details>
   <summary>答案</summary>

課程中演示的 Docker 基本操作流程：

1.  **查看運行中的容器**
    - 命令：`docker ps`
    - 作用：列出當前系統中運行的容器

2.  **拉取鏡像**
    - 命令：`docker pull busybox`
    - 作用：從遠端 Registry 拉取 busybox 鏡像到本地

3.  **查看本地鏡像**
    - 命令：`docker images`
    - 作用：列出 Docker 本地存儲的所有鏡像

4.  **運行容器**
    - 命令：`docker run busybox echo hello world`
    - 作用：從 busybox 鏡像啟動容器，執行 echo 命令輸出 "hello world"

5.  **查看所有容器**
    - 命令：`docker ps -a`
    - 作用：列出所有容器，包括已停止的容器

**關鍵點：**

- 理解鏡像（Image）與容器（Container）的關係
- 掌握基本的 docker 命令格式：docker [子命令] [參數]
- 了解容器執行完命令後會自動停止
</details>

## 第五部分：配對題（15 分）

**Q16.** 請將下列 Docker 術語與其定義進行配對：

| 術語                 | 定義                                        |
| -------------------- | ------------------------------------------- |
| 1. 鏡像（Image）     | A. 執行命令的命令行工具，用戶直接操作的介面 |
| 2. 容器（Container） | B. 後台服務，負責管理鏡像和容器的所有操作   |
| 3. Docker Client     | C. 鏡像運行起來的實例，是隔離的運行環境     |
| 4. Docker Daemon     | D. 存儲鏡像的遠端倉庫                       |
| 5. Registry          | E. 只讀的模板，包含創建容器所需的所有內容   |

   <details>
   <summary>答案</summary>
   <b>1-E, 2-C, 3-A, 4-B, 5-D</b>

- **鏡像（Image）**：只讀的模板，包含創建容器所需的所有內容，類似於虛擬機的快照
- **容器（Container）**：鏡像運行起來的實例，是隔離的運行環境，類似於面向對象編程中「類」與「實例」的關係
- **Docker Client**：命令行工具，接收用戶輸入的命令，向 Docker Daemon 發送請求
- **Docker Daemon**：後台服務進程，真正負責拉取鏡像、創建容器、管理等實際工作
- **Registry**：存儲和分發 Docker 鏡像的遠端倉庫，如 Docker Hub
</details>

**Q17.** 請將下列 Docker 命令與其功能進行配對：

| 命令              | 功能                                    |
| ----------------- | --------------------------------------- |
| 1. docker version | A. 列出本地存儲的所有鏡像               |
| 2. docker info    | B. 從遠端倉庫拉取鏡像                   |
| 3. docker ps      | C. 顯示 Docker 客戶端和伺服器的版本信息 |
| 4. docker pull    | D. 顯示 Docker 系統的詳細信息           |
| 5. docker images  | E. 列出運行中的容器                     |

   <details>
   <summary>答案</summary>
   <b>1-C, 2-D, 3-E, 4-B, 5-A</b>

- **docker version**：顯示 Docker 客戶端和伺服器各自的版本信息、操作系統和架構
- **docker info**：顯示 Docker 系統詳細信息，如容器數量、鏡像數量、CPU、內存、存儲驅動等
- **docker ps**：列出當前運行的容器（加 -a 參數可列出所有容器）
- **docker pull**：從 Registry 拉取鏡像到本地
- **docker images**：列出本地存儲的所有鏡像
</details>
