**Q1.** 在 minikube 環境中,以下哪個命令可以直接登入到 minikube 節點?

A) minikube login
B) minikube ssh
C) minikube connect
D) minikube enter

<details>
<summary>答案</summary>
<b>B) minikube ssh</b> - minikube ssh 命令可以直接登入到 minikube 創建的虛擬節點,在裡面可以執行任意的 Linux 操作。其他選項都不是有效的 minikube 命令。
</details>

**Q2.** 查看 Kubernetes 核心組件(如 apiserver、etcd、scheduler)運行的 Pod 時,應該使用哪個命名空間?

A) default
B) kube-public
C) kube-system
D) kubernetes

<details>
<summary>答案</summary>
<b>C) kube-system</b> - Kubernetes 的核心組件都是以 Pod 的形式運行在 kube-system 命名空間中。使用命令 kubectl get pod -n kube-system 可以查看這些組件。
</details>

---

**Q3.** 創建 YAML 樣板文件時,以下哪兩個參數組合可以生成 YAML 格式的輸出而不實際執行?

A) --dry-run=server -o json
B) --dry-run=client -o yaml
C) --dry-run=all -o wide
D) --no-execute -o yaml

<details>
<summary>答案</summary>
<b>B) --dry-run=client -o yaml</b> - --dry-run=client 參數表示只在客戶端驗證而不實際執行,-o yaml 指定輸出格式為 YAML。這個組合常用於創建資源清單的樣板文件。
</details>

---

**Q4.** 在 Job 物件中,若希望容器失敗後原地重啟,restartPolicy 應設置為什麼?

A) Always
B) Never
C) OnFailure
D) Restart

<details>
<summary>答案</summary>
<b>C) OnFailure</b> - Job 物件的 restartPolicy 可以設為 OnFailure,表示失敗後要原地重啟容器。Always 和 Never 是 Pod 的重啟策略,而 Restart 不是有效的策略值。
</details>

**Q5.** ConfigMap 和 Secret 的主要區別是什麼?

A) ConfigMap 只能存儲字符串,Secret 只能存儲數字
B) ConfigMap 是明文存儲,Secret 經過 base64 編碼
C) ConfigMap 用於開發環境,Secret 用於生產環境
D) ConfigMap 只能在 Pod 中使用,Secret 只能在 Job 中使用

<details>
<summary>答案</summary>
<b>B) ConfigMap 是明文存儲,Secret 經過 base64 編碼</b> - ConfigMap 以明文形式存儲配置信息,可以直接查看;而 Secret 中的數據經過 base64 編碼,類型為 Opaque,不能直接看到原值。兩者都可以在各種 API 物件中使用,且 ConfigMap 要求值必須是字符串。
</details>

**Q11.** 在 Kubernetes 中,ConfigMap 的數據必須是 **\_\_\_\_\_** 類型,建議使用引號包裹以避免解析錯誤。

<details>

## 第四部分:簡答題 (每題 8 分,共 16 分)

**Q13.** 簡述在 Kubernetes 中搭建 WordPress 應用的基本步驟。

<details>
<summary>答案</summary>

**基本步驟:**

1. **創建 MariaDB 數據庫 Pod** - 使用 kubectl apply -f mariadb-pod.yml 創建數據庫容器
2. **獲取 MariaDB Pod 的 IP 地址** - 使用 kubectl get pod -o wide 查看數據庫 Pod 的集群 IP
3. **修改 WordPress 配置** - 更新 WordPress YAML 文件中的環境變量,將 host 改為 MariaDB 的 IP 地址
4. **創建 WordPress Pod** - 使用 kubectl apply -f wp-pod.yml 部署 WordPress 應用
5. **暴露 WordPress 端口** - 使用 kubectl port-forward 將本地端口轉發到 Pod 的 80 端口
6. **配置反向代理** - 運行 Nginx 容器代理轉發的端口,使外部可以通過瀏覽器訪問
7. **訪問 WordPress** - 在瀏覽器中輸入虛擬機 IP 地址,即可看到 WordPress 安裝界面

**關鍵點:**
- 需要確保數據庫先啟動並獲取 IP
- WordPress 需要正確配置數據庫連接信息
- 通過端口轉發和反向代理實現外部訪問
</details>

**Q14.** 解釋 ConfigMap 和 Secret 如何以存儲卷的形式注入到 Pod 中,以及注入後的表現形式。

<details>
<summary>答案</summary>

**注入步驟:**

1. **定義 Volume** - 在 Pod 的 spec.volumes 字段中為 ConfigMap 和 Secret 分別定義存儲卷,指定名稱和引用的 ConfigMap/Secret 名稱
2. **掛載 Volume** - 在 spec.containers.volumeMounts 中將這些存儲卷掛載到容器的指定目錄

**注入後的表現形式:**

- **ConfigMap 注入後:**
  - 每個配置項變成一個獨立的文件
  - 文件名即為配置項的 key
  - 文件內容即為配置項的 value(明文顯示)

- **Secret 注入後:**
  - 同樣每個配置項變成一個獨立的文件
  - 文件名即為配置項的 key
  - 文件內容已經自動經過 base64 解碼,顯示為原始值

**示例:**
```yaml
volumes:
- name: cm-vol
  configMap:
    name: info
- name: sec-vol
  secret:
    secretName: user
volumeMounts:
- name: cm-vol
  mountPath: /tmp/cm-items
- name: sec-vol
  mountPath: /tmp/sec-items
```

**優點:**
- 配置與應用解耦
- 可以動態更新配置(需重啟 Pod 才能生效)
- 支持多個配置項統一管理
</details>

## 第五部分:配對題 (共 25 分)

**Q15.** 將以下 Kubernetes 命令與其功能進行配對:

| 命令 | 功能 |
|------|------|
| 1. kubectl apply -f file.yml | A. 查看 Pod 的運行日誌 |
| 2. kubectl get pod -o wide | B. 進入 Pod 內的容器執行命令 |
| 3. kubectl logs pod-name | C. 創建或更新資源 |
| 4. kubectl exec -it pod-name -- sh | D. 刪除指定的資源 |
| 5. kubectl delete -f file.yml | E. 查看 Pod 列表及詳細信息(含 IP) |

<details>
<summary>答案</summary>

1-C, 2-E, 3-A, 4-B, 5-D

**詳細說明:**

1. **kubectl apply -f file.yml (C)** - 根據 YAML 文件創建或更新 Kubernetes 資源,是聲明式管理的核心命令

2. **kubectl get pod -o wide (E)** - 列出所有 Pod,使用 -o wide 參數可以顯示更多詳細信息,包括 Pod 的 IP 地址、所在節點等

3. **kubectl logs pod-name (A)** - 獲取指定 Pod 中容器的標準輸出日誌,用於排查問題和監控應用運行狀態

4. **kubectl exec -it pod-name -- sh (B)** - 在 Pod 的容器中執行交互式命令,-it 參數保持標準輸入打開並分配偽終端,常用於進入容器進行調試

5. **kubectl delete -f file.yml (D)** - 根據 YAML 文件刪除對應的 Kubernetes 資源,確保資源完全移除
</details>
