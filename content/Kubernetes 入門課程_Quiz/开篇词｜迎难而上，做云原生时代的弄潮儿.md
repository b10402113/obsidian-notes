## 第一部分：選擇題 (40分)

**Q1.** Kubernetes 在容器编排领域的地位如何？

A) 它是众多竞争者之一，尚未确立主导地位
B) 它已经击败了 Docker Swarm 和 Apache Mesos，成为容器编排领域的王者
C) 它仅在小规模应用中使用，大型企业仍使用传统虚拟化技术
D) 它正处于激烈竞争中，未来格局尚不明朗

<details>
<summary>答案</summary>
<b>B) 它已经击败了 Docker Swarm 和 Apache Mesos，成为容器编排领域的王者</b>

解析：文中明确提到 Kubernetes 借助 Google 和 CNCF 的强力"背书"，击败了 Docker Swarm 和 Apache Mesos，成为了"容器编排"领域的王者至尊，地位如同 Linux 一样，成为了事实上的云原生操作系统。
</details>

**Q3.** Kubernetes 技术栈的特点可以概括为哪四个字？

A) 新、快、强、广
B) 大、广、杂、深
C) 新、广、杂、深
D) 新、广、乱、深

<details>
<summary>答案</summary>
<b>C) 新、广、杂、深</b>

解析：作者明确指出 Kubernetes 技术栈的特点可以用四个字来概括："新、广、杂、深"。其中"新"指前沿技术和快速升级，"广"指涉及领域多，"杂"指实现杂乱，"深"指需要深厚技术背景。
</details>

## 第四部分：簡答題 (40分)

**Q16.** 为什么作者认为现在学习 Kubernetes 仍然值得，即使它已经"火"了很久？

<details>
<summary>答案</summary>

作者引用了"艺多不压身"和"机遇总是偏爱有准备的人"这两句话来回答。

<b>关键点应包括：</b>
- "云原生"已经是 IT 界的普遍共识，是未来的大势所趋
- 即使浪潮暂时还没到，但一旦来临，只有提前做好知识储备才能迎难而进，成为"弄潮儿"
- 否则可能会被"拍在沙滩上"
- 作者分享了亲身经历：凭借对容器和 Kubernetes 的积累，在面试时临时准备 20 多页 PPT 就拿下 Offer
- 越早掌握 Kubernetes，将来成功的几率就越大

</details>

---

**Q17.** 请简要描述本课程的四个主要特点。

<details>
<summary>答案</summary>

<b>课程的四个主要特点：</b>

1. <b>没有太多前提：</b> 不需要学习 Go 语言，也不会讲 Kubernetes 源码，降低入门门槛
2. <b>定位在"入门"：</b> 不讲高深理论和复杂流程，语言朴素平实，少用专业术语，建立全局观
3. <b>实战导向：</b> 强调眼手脑结合，鼓励多动手、多实际操作，给出大量操作命令
4. <b>短小精悍：</b> 每节课只聚焦一个知识点，做减法而不是加法，避免发散跑题

</details>

---

**Q18.** 作者为什么选择不讲解 Kubernetes 的源码？请说明理由。

<details>
<summary>答案</summary>

<b>关键理由：</b>

- 讲源码的前置条件太高，不是所有人都具备这个基础
- 为了学习 Kubernetes 要先了解 Go 语言有点"本末倒置"
- 作者引用钱钟书老先生的话："如果你吃了个鸡蛋，觉得味道不错，何必去认识那个下蛋的母鸡呢？"
- 可以对比 Linux 操作系统：它用 C 语言写成，但几乎没人要求学习 Linux 前要先掌握 C 语言
- 如果真想做 Kubernetes 开发，学会基本概念和用法后，再回头学 Go 语言完全来得及

</details>
