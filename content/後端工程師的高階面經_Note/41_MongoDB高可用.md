# MongoDB 高可用機制解析

## 📝 課程概述
本單元深入探討 MongoDB 如何透過分片機制、複製集與寫入語義來實現高可用。從架構設計到實際部署策略,幫助你理解分布式資料庫的核心原理,並為面試做好準備。

## 核心觀念與實作解析

### 為什麼選擇 MongoDB？

在使用 MongoDB 前,首先要理解它相對於 MySQL 等關聯式資料庫的優勢:

**靈活的文檔模型**
- 當資料模型穩定可預測時,適合使用 MySQL
- 當資料結構經常變動、難以預測用戶輸入內容時,MongoDB 更適合

**易於橫向擴展**
- 關聯式資料庫雖可透過分庫分表實現橫向擴展,但難度高、維運複雜
- MongoDB 的分片機制自動化完成,基本不需人為介入

### MongoDB 分片機制

**基本架構**
- **分片集合(Sharded Collection)**: 邏輯表層級
- **分片(Shard)**: 物理表層級,每個分片包含多個塊
- **塊(Chunk)**: 預設 128 MB

**塊的拆分觸發條件**
1. 資料量超過 128 MB
2. 文檔數量超過平均值的 1.3 倍

**自動負載均衡**
MongoDB 的核心優勢在於自動平衡各分片的資料量,不同於傳統分庫分表需要人工預估設計。當資料分布不均時,系統會自動觸發 **再平衡(Rebalance)** 過程。

**再平衡觸發閾值示例**
- 若最大分片有 9 個塊,最小分片有 7 個塊,就會觸發再平衡

**塊遷移七步驟**
1. 平衡器發送 moveChunk 命令至源分片
2. 源分片執行命令,負責讀寫操作
3. 目標分片建立索引
4. 目標分片同步塊資料
5. 最後一筆文檔同步完成後,目標分片啟動增量同步
6. 源分片更新元數據
7. 關閉游標後,源分片刪除塊

### 配置伺服器(Config Server)

配置伺服器存儲關鍵元數據:
- 分片資訊
- 權限控制資訊
- 分布式鎖控制

**重要特性**: 主節點崩潰後仍可提供讀服務,這與大多數中間件不同。配置伺服器是集群核心組件,任何性能抖動都會嚴重影響整個 MongoDB 集群。

### 複製機制(Replica Set)

**架構組成**
- **Primary**: 主實例
- **Secondary**: 副本實例
- Primary + Secondary 合稱 **複製集(Replica Set)**

**資料同步機制**
透過 **oplog** 實現主從同步,類似 MySQL 的 binlog。

**oplog 的兩個缺陷**
1. **容量問題**: oplog 採用冪等設計,任何操作都轉為 set 操作,可能導致空間超乎預期
2. **時效性問題**: oplog 有大小限制,超過限制會被刪除,從節點可能需要重新全量同步

### 寫入語義(Write Concern)

寫入語義對性能、可用性與資料可靠性有重大影響,由三個參數控制:

**w 參數(寫入確認)**
- `majority`: 需同步至大多數節點(預設值),可用性強但性能較差
- `數字 N`: N=1 需寫入主節點;N>1 需寫入主節點與 N-1 個從節點;N=0 不等待任何節點
- 自定義標籤策略: 實務較少使用,但適合面試發揮

**j 參數(持久化)**
- `true`: 資料寫入磁碟
- `false`: 資料僅在記憶體

**wtimeout 參數**
- 寫入超時時間,僅在 w > 1 時生效
- 注意: 超時返回錯誤不代表寫入失敗

### 高可用架構設計

**1. 啟用主從同步**
- 基礎配置: 一主兩從
- 主節點崩潰後可選舉新主節點

**2. 引入仲裁節點(Arbiter)**
- 參與投票但不存儲資料
- 可部署於輕量級伺服器,成本低
- 提高選舉容錯能力

**3. 配置伺服器主從化**
- MongoDB 推薦配置伺服器採用主從結構
- 主節點崩潰後仍可讀取元數據
- 元數據本身為讀多寫少,結合後可用性提升

**4. 多資料中心部署**
- 推薦架構: 兩資料中心,一主三從或一主兩從
- 同資料中心的從節點資料較新,應設置較高優先級
- 單一資料中心崩潰仍可維持服務

### 寫入語義調整策略

**提升可靠性案例**
```
問題: 資料偶發性丟失
排查: Write Concern 的 w 值為 1(僅主節點寫入)
解決: 改為 majority + j=true
```

主節點寫入後崩潰,若從節點未同步,資料即丟失。設置 w=majority 可確保大多數節點都已寫入。

## 💡 重點摘要
- MongoDB 適合資料模型變動頻繁、需橫向擴展的場景,分片機制自動負載均衡
- 分片集合由多個分片組成,每個分片包含多個 128 MB 的塊,系統自動觸發再平衡
- 配置伺服器是集群核心,主節點崩潰後仍可讀取,建議採用主從結構
- 複製集透過 oplog 同步資料,需注意其容量與時效性限制
- 寫入語義直接影響資料可靠性,w=majority + j=true 為推薦配置
