# 資料庫綜合應用：如何確保高可用與高性能

## 📝 課程概述
本單元將前面章節的知識點串聯起來，從查詢優化、參數調優、讀寫分離到分庫分表，建構一套完整的資料庫高性能與高可用方案，幫助你在面試中展現系統性的資料庫實戰經驗。

## 核心觀念與實作解析

### 查詢緩存（Query Cache）

MySQL 的查詢緩存機制以 SQL 語句作為鍵，查詢結果集作為值。當相同的查詢再次執行時，直接返回緩存的結果。然而，**查詢緩存不一定能提升效能**。若每次查詢的 SQL 都不同，反而會降低查詢效能。

在實務上，查詢緩存的最佳使用場景是「複雜查詢」— 掃描大量資料列但只有少數符合條件的查詢。MySQL 8.0 已移除此功能，因為這類查詢在實務上並不多見，且資料庫容易成為效能瓶頸，更適合讓應用層自行處理緩存。

### 參數調優實戰

#### innodb_flush_log_at_trx_commit

控制 redo log 的刷盤時機，是確保資料持久性的關鍵參數，面試必考。

#### innodb_buffer_pool_size

InnoDB 緩衝池大小，用於快取表與索引資料，調大此值可減少磁碟 I/O。

**實務建議**：
- 資料庫伺服器記憶體充足時，可設定為總記憶體的 70% ~ 75%
- 需避免設定過大導致物理記憶體不足，觸發作業系統 swap

**面試案例包裝**：
> 發現資料庫伺服器的 swap 使用率異常高，經排查後發現是 `innodb_buffer_pool_size` 設定過大。採取漸進式調整策略，最終調降至原數值的 70%，swap 大幅減少且查詢效能未受影響。

#### innodb_buffer_pool_instances

當整個 InnoDB 引擎只有單一緩衝池時，所有查詢都會競爭同一個資源，造成嚴重的並發競爭問題。啟動多個緩衝池實例可有效降低競爭。

**實務建議**：
- Buffer Pool ≤ 8G：設定為 2
- Buffer Pool > 8G：設定為 4

**注意**：MySQL 限制當 `innodb_buffer_pool_instances > 1` 時，`innodb_buffer_pool_size` 不得小於 1G。

#### query_cache_min_res_unit

查詢緩存最小分配單位，預設值為 4KB。大多數情況下，4KB 過大會造成記憶體浪費。

**面試案例包裝**：
> 評估業務查詢結果集大小後，發現預設的 4KB 明顯過大。將 `query_cache_min_res_unit` 調整為 1KB，在滿足大多數查詢需求的同時，能緩存更多查詢結果集，提升整體查詢效能。

### 讀寫分離方案

讀寫分離適合尚未實施的小型公司或團隊，能同時提升可用性與查詢效能。

**實施步驟**：
1. 準備一個從庫（Slave）
2. 改造業務代碼，支援動態切換讀主庫或從庫
3. 切換至讀從庫模式，觀察並處理問題

**關鍵挑戰 — 主從延遲**：
原本「更新後立即讀取」的業務邏輯，若改為讀從庫，可能讀到更新前的舊資料。改造過程需特別注意此類場景。

**亮點加成 — 主從自動切換**：
當主庫故障時，能自動將從庫提升為主庫。可使用 KeepAlived 實作簡單的自動切換機制，或直接使用雲服務商提供的功能。

### 分庫分表方案

分庫分表是展現資料庫深度的王牌，若能在公司主導過一次單庫拆分，面試時資料庫關卡基本沒問題。

**方案介紹應包含八個面向**：
1. **為什麼要分庫分表**：說明業務瓶頸與拆分動機
2. **中間件選型**：說明所用中間件的優缺點（推薦 ShardingSphere）
3. **容量規劃**：估算未來成長空間
4. **資料遷移**：平滑遷移策略與回滾機制
5. **分庫分表鍵選擇**：依據業務查詢模式決定
6. **主鍵生成策略**：分散式 ID 方案與選擇理由
7. **分散式事務**：TCC、SAGA 或延遲事務等解決方案
8. **特殊查詢處理**：分頁查詢等跨庫查詢的處理方式

**面試切入點**：
> 參與公司核心資料庫的分庫分表專案，主要負責資料遷移與主鍵生成部分。（這兩個面向技術含量較高，面試更具競爭力）

## 💡 重點摘要

- **查詢緩存已過時**：MySQL 8.0 已移除，因為適用場景有限，且應用層緩存更能減輕資料庫負擔
- **參數調優是基本功**：`innodb_buffer_pool_size` 與 `innodb_buffer_pool_instances` 的搭配調整是經典案例
- **讀寫分離提升可用性**：需注意主從延遲問題，自動切換機制是加分亮點
- **分庫分表是王牌**：涵蓋八個面向的完整方案能展現系統性思維
- **面試策略**：將資料庫高可用、高性能作為提升整體系統可用性的一環來陳述
