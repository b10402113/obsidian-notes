# 中級篇实操总结（視頻課程）

## 📝 課程概述

本課程是「中級篇」的視頻实操总结，透過完整的操作演示，覆盤 kubeadm 搭建集群、Deployment、DaemonSet、Service、Ingress 的實際用法，並演示 WordPress 网站的完整搭建流程，方便學員对照操作上下文學習。

## 核心觀念與實作解析

### 一、安裝 kubeadm

#### Master 節點準備工作（四步）

1. **改主機名**：
   ```bash
   sudo vi /etc/hostname
   # 改成 master
   ```

2. **改 Docker 配置**：cgroup 驅動改成 systemd

3. **改網路設置**：启用 br_netfilter 模块

4. **關閉 Swap 分區**：修改 /etc/fstab

使用脚本自动化：
```bash
vi prepare.sh
./prepare.sh
```

#### 下載 kubeadm

```bash
vi admin.sh
./admin.sh

# 验证版本
kubeadm version
kubectl version --client
# 確認是 1.23.3 版本
```

**注意**：apt install 時要明確指定版本號（如 1.23.3），否則會安裝最新版本。

### 二、安裝 Kubernetes

#### 下載 Kubernetes 组件镜像

```bash
docker images
# 確認有 etcd、apiserver、controller-manager 等镜像
```

#### 初始化 Master 節點

```bash
vi master.sh
./master.sh
```

脚本内容：
- `kubeadm init --pod-network-cidr=10.10.0.0/16 --kubernetes-version=1.23.3`
- 拷贝配置文件到 ~/.kube/config

**重要**：保存 `kubeadm join` 命令輸出（存入 k.txt）

#### 安装 Flannel 网络插件

```bash
vi flannel.yml
# 修改 net-conf.json 的 Network 爲 10.10.0.0/16

kubectl apply -f kube-flannel.yml
kubectl get node
# 確認 Master 状态 Ready
```

### 三、Kubernetes 集群部署

#### Worker 節點安裝

與 Master 相同的準備工作：
- 改主機名
- prepare.sh
- 下載 kubeadm 和镜像

执行 join 命令：
```bash
kubeadm join 192.168.10.210:6443 --token xxx --discovery-token-ca-cert-hash sha256:xxx
```

#### 验证集群

```bash
kubectl get node
# 確認兩個節點都是 Ready

kubectl run ngx --image=nginx:alpine
kubectl get pod -o wide
# 確認 Pod 運行在 Worker 節點
```

### 四、Deployment 的使用

#### 创建样板

```bash
export out="--dry-run=client -o yaml"
kubectl create deploy ngx-dep --image=nginx:alpine $out > deploy.yml
```

#### 部署與管理

```bash
# 修改 replicas 爲 2
kubectl apply -f deploy.yml

kubectl get deploy
kubectl get pod

# 横向扩容
kubectl scale --replicas=5 deploy ngx-dep
kubectl get pod

# 删除
kubectl delete deploy ngx-dep
```

### 五、DaemonSet 的使用

#### 创建样板（從 Deployment 改寫）

```bash
kubectl create deploy redis-ds --image=redis:5-alpine $out \
  | sed 's/Deployment/DaemonSet/g' - \
  | sed -e '/replicas/d' - > ds.yml
```

#### 添加 tolerations

```yaml
spec:
  template:
    spec:
      tolerations:
      - key: node-role.kubernetes.io/master
        effect: NoSchedule
        operator: Exists
```

#### 部署

```bash
kubectl apply -f ds.yml
kubectl get ds
kubectl get pod -o wide
# 確認 Redis 運行在 Master 和 Worker 節點

kubectl delete -f ds.yml
```

### 六、Service 的使用

#### 前置準備

```bash
kubectl apply -f deploy.yml
kubectl get pod -o wide
```

#### 创建 Service

```bash
kubectl expose deploy ngx-dep --port=80 --target-port=80 $out > svc.yml
kubectl apply -f svc.yml

kubectl get svc
kubectl describe svc ngx-svc
```

#### DNS 域名访问

```bash
kubectl exec -it <pod-name> -- sh
curl ngx-svc
curl ngx-svc.default
curl ngx-svc.default.svc.cluster.local
```

#### NodePort 对外暴露

```bash
kubectl get svc
# 查看 NodePort 端口（如 31980）

curl 192.168.10.210:31980
curl 192.168.10.220:31980
```

#### 删除

```bash
kubectl delete -f deploy.yml
kubectl delete -f svc.yml
```

### 七、Ingress 的使用

#### 安装 Ingress Controller 环境

```bash
cat setup.sh
./setup.sh

kubectl get ns
# 確認有 nginx-ingress 名字空间
```

#### 前置準備

```bash
kubectl apply -f deploy.yml
kubectl apply -f svc.yml
```

#### Ingress + Ingress Class

```yaml
# ingress.yml
apiVersion: networking.k8s.io/v1
kind: IngressClass
metadata:
  name: ngx-ink
spec:
  controller: nginx.org/ingress-controller

---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: ngx-ing
  annotations:
    nginx.org/lb-method: round_robin
spec:
  ingressClassName: ngx-ink
  rules:
  - host: ngx.test
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: ngx-svc
            port:
              number: 80
```

#### Ingress Controller

关键配置：
- image: nginx/nginx-ingress:2.2-alpine
- args: `-ingress-class=ngx-ink`

```bash
kubectl apply -f ingress.yml
kubectl apply -f kic.yml

kubectl get ingressclass
kubectl get ing
kubectl describe ing ngx-ing

kubectl get deploy -n nginx-ingress
kubectl get pod -n nginx-ingress
```

#### 测试验证

```bash
kubectl port-forward -n nginx-ingress ngx-kic-dep-xxx 8080:80 &
curl --resolve ngx.test:8080:127.0.0.1 http://ngx.test:8080
```

#### 删除

```bash
kubectl delete -f deploy.yml
kubectl delete -f svc.yml
kubectl delete -f ingress.yml
kubectl delete -f kic.yml
```

### 八、搭建 WordPress 网站

#### 步驟 1：部署 MariaDB

```bash
vi wp-maria.yml
kubectl apply -f wp-maria.yml
```

ConfigMap 環境變量：DATABASE、USER、PASSWORD、ROOT_PASSWORD
Deployment replicas: 1
Service: maria-svc（域名访问）

#### 步驟 2：部署 WordPress

```bash
vi wp-dep.yml
kubectl apply -f wp-dep.yml
```

ConfigMap HOST: **maria-svc**（Service 域名，非 IP）
Deployment replicas: 2（横向扩容）
Service: NodePort，端口 30088

#### 步驟 3：部署 Ingress

```bash
vi wp-ing.yml
vi wp-kic.yml
kubectl apply -f wp-ing.yml
kubectl apply -f wp-kic.yml
```

Ingress Class: wp-ink
Ingress host: wp.test
Ingress Controller args: `-ingress-class=wp-ink`
Ingress Controller: `hostNetwork: true`

#### 步驟 4：验证

```bash
kubectl get deploy
kubectl get svc
kubectl get pod -n nginx-ingress
```

修改 hosts 文件：
```
192.168.10.210   wp.test
```

浏览器访问：`http://wp.test`

## 💡 重點摘要

- kubeadm 安装四步準備：主機名、Docker 配置、網路設置、關閉 Swap
- apt install 需指定版本號避免安裝最新版本
- DaemonSet 樣板可從 Deployment 用 sed 改寫，需添加 tolerations
- Service 域名格式：`ngx-svc`、`ngx-svc.default`、`ngx-svc.default.svc.cluster.local`
- Ingress Controller 关键参数：`-ingress-class` 必须匹配 Ingress Class
- WordPress ConfigMap 的 HOST 必须使用 Service 域名而非 IP
